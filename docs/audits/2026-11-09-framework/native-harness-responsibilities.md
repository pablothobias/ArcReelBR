# Native harness responsibilities and MCP provenance

> Follow-up qualification: [the adapter assessment](mcp-adapter-assessment.md) identifies field-permission and contract issues plus tool-description workflow interference. Earlier keep/access-wrapper classifications are not a guarantee of adapter neutrality. Apply A02 and the current register for dispositions.

Audit date: 2026-11-09. Inspected revision: `1df5ee3b89e865c4193e72d5bbddf64d54b42f0e`. Static source and Git-history investigation only. No application execution, model calls, paid generation, or state repair was performed for this report.

## Finding

ArcReel already contains a production harness. Its embedded main Agent interprets the server's authoritative workflow plan, delegates creative work and review to native subagents, selects versions, edits timelines, and requests paid corrections. Codex does not need to recreate those responsibilities to control production remotely. Remote session controls expose that existing harness; they do not replace it. Current repository policy states this explicitly at `AGENTS.md:7-13`.

“Native” below means owned by the running ArcReel architecture. It does not imply every current feature was inherited unchanged from upstream. In particular, recent personal-fork commits added interfaces and one substantive speech-review capability inside that architecture.

## Provenance and classification

Git history provides concrete evidence that major responsibilities predate the recent Codex-facing additions:

- `5d2612fe7` introduced the authenticated remote MCP endpoint in August 2026, authored by Pollo. Remote access itself was not invented by `5e6626de5`.
- `71bf849a6` introduced Agent video-version selection; `a71711f41` introduced contact-sheet inspection. `05ad9abe2`, authored by Pollo in October 2026, added read-only footage subagents, full first-round review, old/new comparisons, a creator checklist and video-preview quotation. Its diff changes runtime policy, editing skills, native video tools and the video quote service together.
- Existing workflow planning and generation queues also have substantial history predating the recent interface additions. `git log -- <path>` shows planner operation-model changes such as `4ea57ba3b` and queue duplicate-submission fixes such as `b5d147ce4`.

This history supports “inherited native responsibilities” for these features. Only `origin` is configured locally, pointing to the personal repository. No fresh upstream fetch or remote comparison was performed, so this report does not claim that current files exactly match a current upstream release.

The same production declarations feed both hosts: `server/agent_toolset/toolset.py:28-49`, `server/agent_runtime/arcreel_mcp.py:28-35`, and `server/remote_mcp.py:68-73`. Therefore a wrapper's existence is not, by itself, evidence of a second harness.

## Evidence limits and unresolved ownership gaps

Visual footage inspection is contact-sheet review, not listening to generated dialogue. The native reviewer explicitly leaves speech completeness, acting and lip synchronization unassessed (`agent_runtime_profile/.claude/agents/review-footage.md:11-13`). The newer speech evaluator requires exact normalized word agreement and reliable bounds before applying timing and explicitly emits `lip_sync=not_assessed` and `vocal_performance=not_assessed` (`lib/speech/audio_review.py:104-159`). Word recognition and subtitle timing do not close identity, acting or lip-sync acceptance.

Existing validation documents report bounded local exercises and selected checks, not universal validation: `docs/testing/native-mcp-production.md:20-30` describes the resumed delivery and earlier preparation outside MCP; `docs/testing/native-speech-review.md:13-31` describes retained-unit timing/render checks and remaining audiovisual limits. Those are historical repository claims. This audit did not rerun their checks, inspect private transport receipts, or independently approve their output. Source presence establishes intended ownership and implemented seams; it cannot establish unattended end-to-end reliability.

For the overall duplication assessment, compare Codex customizations against the ownership map above. An external controller that preserves authorization, supplies original inputs, answers already-authorized questions and monitors native sessions fits the present boundary. An external controller that chooses shots, writes production prompts, ranks candidates, directs each retry or edits output has taken over responsibilities already present in the embedded harness. Whether particular historical interventions were justified by access gaps requires the separate intervention/session audit.
