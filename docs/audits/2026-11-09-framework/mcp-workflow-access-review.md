# MCP workflow-access source review

> Follow-up: [R10/R11 isolated reproductions](r10-r11-isolated-reproduction.md) supersede the unexercised-risk status of MA04/MA05 and narrow the storyboard-quote migration claim. This document records the earlier source-only review.

Date: 2026-11-09. Scope: `b88d14cd0` and its parent, current `server/media_tools/workflow_access.py`, its declarations, and the Settings/upload/image-edit seams changed in that commit. This is documentation-only research under A02 in [the register](refactor-register.md). No production, model calls, authentication subprocesses, configuration changes, test additions, or test execution occurred. Findings below are source conclusions, not reproduced editorial outcomes.

## Confirmed workflow interference in descriptions

### MA01: the cost reader adds a mandatory pre-action quotation instruction

`server/agent_toolset/workflow_access.py:85-86` says: "Use quote_assets/quote_storyboards or generate_videos preview before paid actions." This is a new caller instruction in the tool declaration, not required to implement a cost reader. The declaration did not exist in `b88d14cd0^`. The original native asset skill did not require this separate quotation stage, as recorded in W04 of [the workflow review](workflow-interference-review.md).

This instruction remains active even if the corresponding CLAUDE/skill clauses are removed. The declaration enters the shared toolset at `server/agent_toolset/toolset.py:25-30`; the embedded server presents its description at `server/agent_toolset/embedded.py:52-56`, and the remote host uses it at `server/agent_toolset/remote.py:98-102`. Therefore it directs both the embedded Agent and an official external MCP client. Reusing native implementation does not make this sequencing instruction neutral.

Recommended disposition under A02: remove the blanket sequencing sentence, while keeping the reader, optional quote/preview capabilities, honest unknown-cost semantics, actual user spending limits, and original native confirmation rules. This is a proposed source disposition, not implementation authorization. No demonstrated editorial failure is required for this interference finding.

### MA02: full-ledger pagination is purpose-scoped API guidance

`server/agent_toolset/workflow_access.py:97` says: "Follow next_cursor until null to reconcile the full ledger." The purpose clause scopes this instruction to full reconciliation. The handler supports bounded pagination (`server/media_tools/workflow_access.py:146-164`). The wording alone does not require every caller or production stage to exhaust the ledger.

Recommended disposition under A02: preserve pagination guidance, cursor mechanics and the distinction between null and zero cost. No mandatory workflow removal is justified from this sentence alone. The earlier interpretation that it unconditionally imposed full reconciliation has been withdrawn; actual compulsory profile stages remain covered by W05.

### MA03: distinguish narrower purpose guidance from a universal preflight

`server/agent_toolset/workflow_access.py:38` says to use Settings for explicit requirements before generation. Unlike MA01, it is scoped to explicit requirements and does not literally order a configuration call for every production. `:51` points to the capabilities tool for route-specific audio/reference facts. `:63-64,74,86,97` explain financial uncertainty. These clauses should not all be called mandatory extra stages solely because they contain imperatives.

The stronger universal configuration/accounting stages in the CLAUDE profiles remain separately covered by W03/W05. Preserve factual contract guidance while removing imposed stages; the source here does not establish that all seven tools form another production harness.

## Source-qualified implementation risks, separate from A02 interference

### MA04: some diagnostic/preview reads can persist legacy script migrations

The storyboard planner calls `projects.load_script` (`server/services/admission/storyboard_batch.py:153-154`) and explicitly documents migration persistence (`:392-393`). `get_project_costs` also loads scripts through this writing reader (`server/media_tools/workflow_access.py:127-139`); storyboard image-edit preview does the same (`server/media_tools/image_edits.py:254-272`). `ProjectManager.load_script` persists compatibility conversion when required (`lib/project/project_manager.py:1386-1409`), while `load_script_readonly` exists at `:1412-1416`.

Thus these operations can write a legacy script despite their diagnostic/preview role. This is conditional on supported legacy data, not a claim that every quote writes. It does not establish provider calls, job creation, creative rewriting, or an external production controller. `quote_storyboards` promises no provider calls/tasks rather than literally no filesystem writes; image-edit preview's field description is limited to "image writes." Nonetheless, a blanket assertion that all these tools are filesystem read-only is false, and tests proving no usage does not establish no writes.

`get_project_costs` performs its `load_script` loop with ordinary `asyncio.to_thread` (`server/media_tools/workflow_access.py:139`), whereas the native storyboard planner explicitly uses `run_sync_transaction` to wait for any migration write (`server/services/admission/storyboard_batch.py:392-393`). This creates a conditional cancellation/completion risk for the new cost endpoint: the cancelled caller can finish before a migration write completes. It matches the backend rule "Use `run_sync_transaction` for threaded formal-file writes or temporary-artifact creation" in `docs/standards/backend.md`. This is source-supported; it was not exercised. Prefer a genuinely read-only reader for diagnostics or explicitly preserve the native transaction semantics if migration writes are intended. Do not remove native migrations as workflow interference.

### MA05: the new existing-character image-upload guarantee is only an entry check

`require_reference_host` is checked at `server/routers/files.py:570-573`, then image bytes are written at `:637-638`, and metadata is updated at `:643-644`. If the character is deleted by another supported request between the check and metadata update, the setter raises `KeyError` (`lib/project/project_manager.py:3817-3821`). Cleanup/refusal happens only when `spec.host_bucket` is set (`server/routers/files.py:645-654`), but the character-image-reference spec has no such host bucket (`:240-246`). The helper can therefore report success with an orphan reference after that race.

The permissive missing-host behavior was inherited from Web single-image uploads. The new MCP entry promises an existing named character and adds a precheck, but does not strengthen the commit-time invariant. This is a reachable concurrency risk and a contract limitation of the new promise, not a proven historical production incident. The backend rule "Recheck state prerequisites after `await`; when stale, record current state or skip side effects" explicitly includes checks outside a write lock. A later fix would need to preserve intentional Web semantics while making the promised MCP invariant transactional; this audit does not authorize that fix.

### MA06: external image-edit preview receives contradictory batch-polling guidance

`EDIT_IMAGES` remains a `generation_tool` (`server/agent_toolset/media_generation.py:110-119`), and that factory always sets `long_task=True` (`:54-78`). For remote callers, `server/agent_toolset/remote.py:98-102` consequently appends the generic note at `:39-42`, saying external calls return a `generation_batch` handle and must be polled. The new `preview=true` handler instead returns `image_edit_quote` and a generation result before reaching submission (`server/media_tools/image_edits.py:310-325`). It creates no batch handle to poll.

This is a confirmed description/response-contract mismatch introduced when adding this preview form. It is not evidence that the implementation submits duplicate jobs, that a remote caller actually tried to poll a nonexistent batch, or that preview itself performs a paid call. A later correction should condition the remote long-task guidance on actual submission and accurately describe immediate preview results. The inherited `generate_grid` list-only preview already has a similar generic-note tension, with custom result hooks and explicit no-queue guidance (`server/agent_toolset/grid_storyboards.py:19-28`); that inherited case is not attributable to this commit.

## Existing tests inspected and evidence limits

- `tests/integration/server/test_workflow_access.py`: Settings persistence and invalid requests, explicit `pt-BR`, successful image reference upload with no sheet generation, unsafe/unconfirmed inputs, scoped usage pagination and diagnostic omission, asset target/cost selection with zero recorded usage, effective configuration with a non-subscription model, unpriced i2i, and missing episodes.
- `tests/integration/server/media_tools/test_image_edits.py:414-435`: optional edit preview returns targets/unknown pricing, leaves source-image bytes unchanged, and avoids the injected submission path.
- `tests/integration/server/agent_toolset/test_host_consistency.py`: both hosts project the shared declarations, schemas, descriptions, migration policies, and result envelopes. Its module contract expressly says fake-handler adapter tests observe passthrough, not handler behavior.

None was executed here. The inspected new integration tests do not establish full Settings parity across all fields, confirmed style-analysis success/failure/cancellation, subscription subprocess behavior, successful storyboard quoting, old-script filesystem purity, or the concurrent-deletion upload guarantee. They do not test production acceptance or prove instructions harmless. Their fixtures use isolated data roots, but no new execution was needed for the source findings.

## Disposition

Preserve native tools, pt-BR content support, Settings/ref-upload capabilities, financial evidence, optional native quotation/preview, and original authorization safeguards. Add MA01 to the instruction-removal inventory under A02. MA02 is purpose-scoped API guidance and does not justify another removal item. Track MA04/MA05/MA06 as separate implementation/contract risks; they are not reasons to retire the native capability. No source changes or tests are included in this audit.
