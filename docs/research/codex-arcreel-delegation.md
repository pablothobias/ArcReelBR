# Codex orchestration of the embedded ArcReel Agent

> Historical research proposal. The user subsequently required creative planning and review to remain in the native ArcReel Agent, with Codex automating existing interfaces through MCP. The proposed director skill below is not current production authority; follow `AGENTS.md` and the native framework.

Research date: 2026-11-08. Scope: a personal, locally running ArcReel and a Codex desktop conversation that makes creative decisions while the embedded Claude Agent performs the work. This is an architecture assessment, not an implementation or a live end-to-end test.

## Recommendation

Pair a dedicated Codex skill with the ArcReel MCP endpoint. The skill supplies the decision and review workflow; MCP supplies callable operations. Add a small session-control surface that invokes the existing assistant service in the server process. Keep the existing remote production tools for project inspection and media review. The skill is not an independently running service, does not itself provide MCP tools, and does not guarantee automatic background work after a Codex turn ends. [OpenAI's customization overview](https://learn.chatgpt.com/docs/customization/overview#skills) describes reusable skill instructions, implicit and explicit invocation, and pairing skills with MCP.

## Existing implementation

- The existing [`video-workflow` skill](../../skills/video-workflow/SKILL.md) makes the external Agent route production directly through remote tools. It is a useful source of project-plan semantics, but its orchestration model differs from delegating execution to the embedded Claude Agent.
- The [`setup-arcreel-skills` skill](../../skills/setup-arcreel-skills/SKILL.md) configures and verifies the current remote endpoint; it does not provide session control.
- The [remote host](../../server/remote_mcp.py) is streamable HTTP at `/mcp` and requires a bearer `arc-` key. [Remote tool registration](../../server/agent_toolset/remote.py) projects the declared production toolset, rather than the assistant session routes.
- The [assistant router](../../server/routers/assistant.py) offers send/create, session metadata, cursor-based entry retrieval and SSE, pending-question answers and interrupt. The [assistant service](../../server/agent_runtime/service.py) forwards sends to the embedded session manager. The [options assembler](../../server/agent_runtime/options_assembler.py) builds the SDK options including profile instructions, hooks, sandbox, and in-process ArcReel tools.
- A send may be accepted or queued; `client_key` supports idempotent retry. An MCP bridge must preserve those distinctions and project/session ownership. A result event alone is not a reliable completion signal: the [entry stream](../../server/agent_runtime/service.py) emits subsequent session state after the turn entries. The stream initially sends pending questions and later changes; the cold entries endpoint does not itself return the pending-question snapshot. A polling adapter must obtain pending questions separately or correctly consume the stream, and must not equate silence with completion.
- [`inspect_images`](../../server/agent_toolset/image_review.py) and [`inspect_video_units`](../../server/agent_toolset/video_review.py) return image content. The latter returns sampled contact sheets and local black/freeze/cut signals, not an audio-visual review of every frame; its `model_review` is always null. Full playback, audio, subtitle and lip-sync evaluation require additional verified access and appropriate analysis capabilities. [File preview routes](../../server/routers/file_view.py) are a possible access path, but their use from Codex has not been tested.
- [`agent_language_rule`](../../lib/prompts/prompt_templates/templates/text/agent_language_rule.md) separates reply language from the creative content language. Current server-supported locales do not include Portuguese ([i18n](../../lib/i18n/__init__.py)). A bridge alone does not establish reliable Portuguese replies or creative-output quality.

## Expected operation and boundaries

User invokes a dedicated skill (for example `$arcreel-director`) in a local Codex conversation, naming the project and creative goal. Codex retrieves authoritative project state, chooses a next action, submits it to the existing embedded Agent, tracks its session, reads questions and results, examines available artifacts, and decides whether to continue or report a concrete blocker. A skill can encode these steps and stop conditions; service-side controls still enforce permissions and business rules. Existing `video-workflow` instructions requiring user decisions at branches should be reconciled with the user's authorized autonomy rather than blindly combined with a new director skill.

Before claiming the workflow works: test a real local session using the existing authenticated Claude setup; verify accepted/queued messages, idempotent retries, question visibility and answering, terminal status, restart/reconnect, output inspection, and costs. An active ArcReel backend, a configured Codex MCP connection, and an `arc-` credential are required. The user's tested local Claude Max behavior is evidence of their current setup, not proof of this unimplemented bridge. [Anthropic's authentication guidance](https://code.claude.com/docs/en/legal-and-compliance) distinguishes individual Claude Code use and Agent SDK product authentication; this research does not establish a definitive interpretation for this personal configuration.
